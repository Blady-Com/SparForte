Logs Package

This package contains routines for creating simple program log files.

Introduced: SparForte 2.2

GCC Ada Equivalent: none

Help Command: Contents of the logs package

A log file records events that occur while a script is running, mainly to assist with debugging and security audits.

A script may open only only one log at a time. If no log is open, the logs package writes messages to current_error (which is standard_error, if it is not redirected).

Logs have mode to change the method of writing the log. logs.log_mode is an enumerated type with the following values:

  • log_mode.stderr - the log is written to current_error
  • log_mode.file - the log is written to a file
  • log_mode.echo - the log is written to both current_error and a file

Log messages have severity levels. In increasing severity, they are info, warning and error. An ok message means an operation was successful.

Log messages may have an nesting level. Increasing the level increases the indentation of the message. Nesting groups related messages and shows dependencies.

When you record an event in a log, the message may not be written immediately to the log. The message may be buffered. The logs package checks for duplicate messages and replaces them with a message "..repeated n times" where n is the number of times.

Chaining Messages

logs.ok and the other logging message functions may be run in a chain with "@". The messages will be concatenated together to form the full message. The following writes one line to the log file:

logs.info( "Connecting to " ) @ ( service );

Format of the Log File

05/21 12:19:39:31283:logs:OK:logs:13::this is OK

The log file message has a series of colon-delimited fields:

  • Timestamp - the date and time of the entry
  • PID - the process id
  • Enclosing Entity - the name of the script (or subprogram)
  • Severity - the severity level
  • Filename - the file where the error occurred
  • Line number - the current line number in the program
  • Width Spacer - contains enough spaces to reach the column width defined in logs.open
  • Message - the log message

Except for the timestamp field, other fields are escaped for colons and by strings.to_escaped.

Log Width and Nesting

To make log files more readable by humans, specify a header width and a nesting level. The header width helps to line up messages at the same position on a line. The nesting level indents messages to show how messages relate to one another.

05/21 12:19:39:31283:logs:OK:logs:13:       :this is width 45
05/21 12:19:39:31283:logs:OK:logs:134:      :  this is a new level

logs.close

 

Closes the log. Writes any outstanding log messages to the log file.

Example

logs.close;

Parameters

Exceptions

logs.metrics( o, i, w, e )

 

Return simple metrics of what the script has written to the log. The metrics are gathered since the log was opened or since the last checkpoint. Automated messages like those for repeated lines are not included.

Example

logs.metrics( ok_count, info_count, warning_count, error_count );

Parameters
Param Mode Type Default Description
o out natural required the number of ok messages
i out natural required the number of info messages
w out natural required the number of warning messages
e out natural required the number of error messages

logs.open( p, m [,w] )

 

Creates or resumes a log at path p, in mode m, where messages begin at minimum character position w. If mode is stderr, the path is ignored.

Example

logs.open( "/var/log/script.log", log_mode.file, 40 );

Parameters
Param Mode Type Default Description
p in string required the pathname of the file
m in logs.log_mode required how the logs are to be written
w in positive 1 the minimum width of the header

Exceptions

log is already open
log path is an empty string
log path should be an empty string
log path is a directory
log path does not exists
no permission to write the log file

See Also
